# 迭代修改协议

用户在首次方案后提意见、调参数或要求修改时，按本协议执行。

## 0. 最常见入口：上传不满意的图 + 文字说明
用户直接发一张已出好的设计图，并写"改哪里、怎么改"时，按这个最短路径处理：
1. 这张图是本地文件就先上传转成 URL；是对话里刚生成的图就用它的 URL。
2. 用 `image_edit`，`image_reference_url_list` 只传这张图。
3. prompt 写清：保留什么（其余画面、产品、色调、字体不动）+ 用户说的改哪里 + 改成什么样。例如"保留整体暖调灶台背景和标题，把锅里锅巴换成更满更金黄的状态，主标题改为"XX""。
4. 只改这一张，不动其他屏。出图后单独交付这张。
5. 用户没说要改的元素一律不碰，不擅自加戏。

## 1. 先分类用户反馈
- **参数调整**：张数、比例、分辨率、整体风格、色调、字体、价格定位、目标人群。
- **单屏修改**：某屏文案不对、画面不对、产品没对齐、文字乱码。
- **方向调整**：换风格（乡土→高级、暖调→冷调）、增删屏次、换叙事重点。
- **竞品参考**："看看同行怎么做""参考淘宝上同类产品"。

## 2. 定位受影响范围，最小改动
- 单屏问题：只重画/重写该屏，其他屏不动。
- 参数调整（如整体换色调）：改全局视觉锚点，受影响屏次重出；不变的屏保留。
- 方向调整：先确认新方向，再分批重出，不要一次全推翻。

## 3. 改图方式
- 已有生成图 URL 时，优先 `image_edit` 传入该图 URL 做局部修改，prompt 写清"保留 XX，把 YY 改成 ZZ"。
- 保持全局视觉锚点一致：同一套主色、光源方向、字体气质。
- 产品外观仍以原始产品图为锚，不能改着改着产品变了样。

## 4. 调整依据（三个来源）
- **用户意见**：最高优先级，直接执行。
- **内置知识库**：`page-templates.md` 的品类权重与版式规则，`product-analysis.md` 的分析框架。
- **竞品共性**：用户要求参考同行时，用浏览器/搜索打开淘宝、京东、拼多多同类商品 Top 详情页，记录：他们都有哪几屏、主打什么卖点、怎么排参数、什么色调。提炼共性后，结合本品差异化表达，不照抄文案。

## 5. 迭代后交付
- 说明改了哪几屏、为什么改。
- 只重新交付改动的屏 + 链接，不必重发全套。
- 持续记录当前已确认的全局锚点（色板、字体、光源），下一轮默认沿用，除非用户要求改。

## 6. 常见参数调整速查
| 用户要求 | 调整动作 |
|---|---|
| 更高级/更大气 | 压暗背景、留白≥40%、减色到≤2种、换极简无衬线 |
| 更促销/更热闹 | 加红橙撞色、大标题、利益标签（不写价格除非用户给） |
| 更生活/更种草 | 场景化、自然光、手账感、手写体 |
| 字数太多/太挤 | 每屏只留 1 主标 + 1 副标，删支撑小字 |
| 产品不像了 | 重传产品图，所有屏以它为 [img0] 重出 |
